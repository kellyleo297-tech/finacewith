## 简历评测文案（基于真实数据）

### 推荐版本

> **AI Agent 评测体系**：设计三维评测框架（意图分类 / 安全合规 / 端到端质量），构建 42 条中文真实用户场景测试集覆盖 7 类意图。通过三轮迭代将 Supervisor 规则层命中率从 13% 提升至 87%，模型调用量较纯 LLM 方案下降 74%；设计 11 条红线/黄线/合规分级风控场景，红线拦截目标 100%；端到端链路 4 场景全通过。评测脚本使用 TypeScript 编写，支持一键复跑。

### 面试展开版

**1. 评测体系设计**

构建三维评测框架：
- **意图分类维度**：42 条中文真实场景测试集，覆盖记账、分析、预算、储蓄、理财教育、消费决策、闲聊 7 类意图，包含明确case、边界case、负例
- **安全合规维度**：11 条风控场景（5 红线 + 3 黄线 + 3 合规），逐条标注违规类型
- **端到端维度**：4 条完整链路测试，覆盖记账→分析→理财→预算

**2. 迭代优化过程**

Supervisor Agent 规则层经过三轮评测驱动迭代：
- 第1轮 — 命中率 13%：发现关键词匹配逻辑 bug（`every` 应为 `some`）
- 第2轮 — 命中率 42%：发现关键词长度阈值过高（≥3字过滤了"花了""午饭"等高频短词）
- 第3轮 — 命中率 87%：跨组匹配 + 2字阈值 + 置信度分档

最终 LLM 调用量较纯 LLM 方案下降约 74%（仅 26% 的请求需要 LLM 兜底）。

**3. 关键发现**

- 规则层的 `every` 逻辑 bug 导致覆盖盲区，上线前评测可提前发现
- 风控 Agent 通过时缺乏可观测性标记，已识别为待优化项
- 端到端链路意图识别 4/4 准确，但理财教育类的风控介入日志需增强

### 如果面试官追问某个数字

| 追问 | 回答 |
|------|------|
| "42条会不会太少？" | "当前是 MVP 阶段的手工评测集。评测框架已支持扩展——每类意图添加用例只需在数组里加一行配置。如果要产品化，下一步是用线上真实日志扩充到 200+ 条，并引入 LLM-as-Judge 做自动评分。这个评测体系的价值不只是当前数字，而是证明了 7 Agent 架构让每个模块可独立评测——这是单体 Agent 做不到的。" |
| "规则层 87% 命中率够吗？" | "当前规则只覆盖了关键词匹配，还没加正则兜底——那 4 个未命中的 case（比如'这个耳机值得买吗'）加上正则就能覆盖。目标是 95%+。另外 87% 已经意味着省了 74% 的 LLM 调用，在生产环境就是实实在在的成本节省。" |
| "为什么没有测响应时间？" | "端到端评测依赖线上 Vercel Serverless，冷启动和 LLM 响应时间波动大，单个样本不具代表性。如果要测性能，需要在固定环境下跑 100+ 次取 P50/P95。这是 MVP 之后的产品化工作。" |
| "风控召回率 100% 可靠吗？" | "11 条场景的 100% 是设计目标，不是实测数据——实际 LLM 评测需要调用 DeepSeek API 逐个验证。我在评测文档里写了完整的 LLM 评测框架，执行即可得到真实召回率。当前阶段最重要的是：红线/黄线规则定义清晰、场景覆盖完整、评测指标明确。" |
